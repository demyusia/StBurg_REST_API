## Автоматизация тестирования REST API

В рамках этого проекта был разработан фреймворк для автоматизации проверки бизнес-логики бэкенда приложения `Stellar Burgers`. Тесты покрывают ключевые эндпоинты управления пользователями и заказами.

## Стек технологий
* **Язык разработки:** Java 
* **Тестовый фреймворк:** JUnit 4
* **Взаимодействие с API:** RestAssured
* **Тестовые данные и утилиты:** JavaFaker, Lombok (`@Getter`, `@Setter`), Gson (сериализация данных)
* **Сборщик проектов:** Maven
* **Отчетность:** Allure Report

---

## Реализованный функционал и покрытие тестами

### 1. Управление пользователями (User API)
* **Регистрация:** 
  * Успешное создание уникального пользователя.
  * Защита от повторной регистрации пользователя с уже существующими данными.
  * Валидация ошибки при попытке регистрации без заполнения одного из обязательных полей.
* **Аутентификация (Логин):**
  * Успешный вход под существующим пользователем.
  * Обработка ошибок при авторизации с неверным логином или паролем.

### 2. Управление заказами (Order API)
* **Создание заказа:**
  * Успешное оформление заказа авторизованным пользователем.
  * Проверка логики создания заказа без предварительной авторизации.
  * Создание заказа с валидным списком ингредиентов.
  * Валидация ошибки при отправке заказа без ингредиентов.
  * Обработка ошибки при передаче неверного хеша ингредиента.

## Архитектура проекта и работа с данными

* **Динамические данные (JavaFaker):** Использована библиотека `JavaFaker` для генерации случайных уникальных данных пользователей (email, имя, пароль) перед каждым запуском. Это обеспечивает независимость и изолированность тестов.
* **Сериализация (Gson + Lombok):** Для отправки данных в API-запросах созданы Java-модели. Аннотации Lombok `@Getter` и `@Setter` позволили освободить кодовую базу от шаблонных методов доступа. Библиотека `Gson` применяется для автоматической сериализации созданных Java-объектов в формат JSON.
* **Разделение слоев (API Clients):** Логика отправки HTTP-запросов вынесена из самих тестов в отдельные классы-клиенты (`UserSteps`, `OrderSteps`, `UserData`, `OrderData`). Это упрощает чтение, поддержку и масштабирование фреймворка. 
* **Очистка данных (Cleanup / Teardown):** В блоке `@After` реализовано автоматическое удаление созданных пользователей и заказов после каждого выполненного теста. Это предотвращает загрязнение базы данных тестового окружения и гарантирует стабильность последующих прогонов.

## Запуск тестов и генерация Allure-отчета

### 1. Запуск автоматических тестов
Для прогона всего тестового набора выполните в терминале команду:
```
mvn clean test
```

### 2. Просмотр отчетов Allure
После завершения тестов соберите и откройте интерактивный Allure-отчет в браузере с помощью команды:
```
mvn allure:serve
```
